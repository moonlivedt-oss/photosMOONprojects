# Политика безопасности

## Как сообщить об уязвимости

Пожалуйста, **не открывай публичный issue** для проблем безопасности. Вместо этого:

- воспользуйся приватным каналом GitHub - вкладка **Security → Report a vulnerability**
  (GitHub Security Advisories) в этом репозитории;
- либо напиши автору через профиль [@moonlivedt-oss](https://github.com/moonlivedt-oss).

Опиши, что нашёл(ла), как воспроизвести и в чём потенциальный вред.

## Что важно знать о модели угроз

«Библиотека картинок» - локальное окно на PyQt6 и набор скриптов. Оно **не открывает сеть** и не
собирает телеметрию. Основной вход данных - файлы картинок (из входящих, перетаскиванием, из
буфера, из папки генератора) и страница `Prompts.html`. Поэтому:

- **Сеть - только `get_models.py`.** Он качает модели CLIP с Hugging Face по HTTPS; окно и
  командная строка в сеть не ходят.
- **Картинки читает Pillow.** Битый или специально испорченный файл - главный путь атаки;
  держи Pillow обновлённым. Тяжёлая обработка идёт в отдельных процессах.
- **`Prompts.html` выполняется через node** (`library/prompts.py`), чтобы окно видело те же имена и
  маршруты, что и страница. Это локальный файл проекта; не подменяй его чужим.
- **Запись только в папку библиотеки и в выбранную папку выгрузки.** Удаление - в корзину Windows,
  отменённое ждёт в `_sources/_undone`.
- **ИИ-помощники (MCP).** Сервер `_tools/mcp_server.py` запускает сам клиент помощника, общение - по
  stdin/stdout, сети у сервера нет. Операции принимают только пути внутри библиотеки (кроме чтения
  файлов для `import_images`, `similar` и папки назначения `export`), ничего не стирают (удалённое -
  в `_sources/_deleted`) и пишут журнал, который окно показывает и отменяет. Запись можно запретить:
  «ИИ-помощники» -> «Только искать и смотреть». Картинки, которые помощник смотрит, уходят его модели.

Если ты нашёл(ла) способ выполнить код через содержимое картинки, имени файла или `Prompts.html`,
заставить окно ходить в сеть или писать вне библиотеки - сообщи приватно.
