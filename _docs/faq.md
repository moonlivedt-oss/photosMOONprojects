# Вопросы и решение проблем

**`Library.cmd` пишет «Нужны пакеты», хотя всё стоит.**
Скорее всего, у `.cmd` окончания строк LF вместо CRLF: после `chcp 65001` командная строка путает
строки, в выводе видно обрезанное `ONTWRITEBYTECODE`. В репозитории это закреплено
`.gitattributes`; если файл правился вручную - сохранить его с окончаниями CRLF. Если пакетов правда нет -
`Установить.cmd` (в архиве релиза) или `py -3.14 -m pip install -r _tools/requirements.txt`.

**Нет кнопки-шара и подсказок меток.**
Нет моделей: `py -3.14 _tools/get_models.py`. Проверить: в `_tools/_models/clip` четыре файла.

**Внизу окна «Поиск по смыслу: учу картинки…».**
Окно считает векторы новых картинок. Поиск заработает, когда счётчик дойдёт до конца.

**Помощник не видит библиотеку.**
Окно «ИИ-помощники» показывает, какие помощники установлены и подключены; после подключения клиента его нужно
перезапустить. Проверить сервер без помощника: `py -3.14 _tools/cli.py api overview`.

**Помощник сделал не то.**
«История» внизу окна или кнопка «Отменить» в сообщении; в окне «ИИ-помощники» - список всех его действий.

**Окно повело себя странно или закрылось.**
Ошибки пишутся в `_tools/_errors.log` - приложи его к issue. Если окно закрылось со сбоем, при следующем
запуске оно само скажет об этом и предложит проверку; после двух сбоев подряд включается безопасный режим
(живой 3D во вкладке Unreal выключен).

**Пропали метки, заметки или настройки; что-то сломалось.**
«Инструменты» -> **«Проверка и восстановление»** (или Ctrl+P -> «Проверка»): состояние настроек, базы,
резервных копий, моделей и места на диске, «Починить» одной кнопкой и список копий с «Вернуть выбранную».

Как это устроено:

| Что | Как защищено |
|---|---|
| Метки, заметки, избранное, умные папки, журнал отмены (`library.db`) и настройки (`settings.json`) | копия раз в день при запуске в `_tools/_backups/`, хранятся последние 10; копия базы - через backup API SQLite, целая даже при открытом окне и сервере MCP |
| Повреждённые настройки | окно не стартует с пустыми (иначе записало бы их поверх): файл отодвигается в `settings.json.broken-<время>`, берётся последняя целая копия |
| Повреждённая база | так же: `library.db.broken-<время>` и последняя целая копия; если копий нет - новая база (отпечатки и векторы пересчитаются сами) |
| Запись файлов | через временный файл и `fsync`: сбой или отключение питания не оставят пустышку |
| Возврат копии | текущее состояние сначала само уходит в копию «перед восстановлением» - передумать можно |

**Окно вообще не запускается.**
Двойной щелчок по `_tools/repair.cmd` - проверка и починка без окна. То же из консоли:

```bash
py -3.14 _tools/cli.py repair                 # проверить
py -3.14 _tools/cli.py repair fix             # починить что можно
py -3.14 _tools/cli.py repair list            # резервные копии
py -3.14 _tools/cli.py repair restore latest  # вернуть последнюю
```

**Картинка лежит боком.**
Некоторые jpg хранят пиксели повёрнутыми и флаг EXIF «поверни». Окно читает всё с учётом флага;
если боком в другой программе - это её особенность.
